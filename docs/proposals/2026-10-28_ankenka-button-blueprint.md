## 0. 約束（大ちゃんが決めたこと）

- 案件化ボタンは **前半（ボタン）＋後半（オートメーション）**。**後半だけを** カスタムエージェントにする。全部は変えない。
- 売主は **売り手企業**（法人）か **売り手個人**（個人）に入れる。「関連企業」には入れない。
- 売主が設定されていなければ **エラー**（大ちゃん 10/27）。予定粗利額と根拠が入っていることも条件（問い合わせの案件化ボタンの説明）。
- 問い合わせの **担当営業ユーザー** は、案件化すると案件の **仕入れ担当** に移る。案件の **担当営業ユーザー**（販売側）は空で始まり、案件側の「商談をする」を押した人がなる（商談をする＝担当になる）。案件管理DB に「販売担当」という列は無い。
- 名前は案件管理DB にもう決まっている：**案件名**＝通称名、**正式名称（通称名）**＝対外用の名前。列は増やさない。
- 購入希望のお客様は案件化しない。
- **発電所詳細資料は、問い合わせの段階でお問い合わせDB から作る（案件管理DB からは作らない）。案件化のとき、その資料を新しく作らずに案件へ引き継ぐ（大ちゃん 2026-10-29。大事なこと）。**
- 本番を変える前に OK を取る。エージェントを作るのも、承認ボタンを押すのも大ちゃん。

## 1. 全体の流れ

```
お問い合わせ「案件化する」
│
├─ 前半（Notion 標準のボタン・AI なし・条件で止められない）
│    確認を表示 → 案件管理DB にページを追加 → 案件化メモに「受付」 → 追加した案件を開く
│
└─ 後半（カスタムエージェント・案件管理DB に案件が追加されたら起動）
     ①起動の確認 → ②二重の確認 → ③前提の確認（足りなければここで止まる）
     → ④売主 → ⑤担当（一時） → ⑥中身を移す → ⑦名前 → ⑧子ページ
     → ⑨ゲート（不足の洗い出し・担当を仕入れ担当へ移す） → ⑩本文・コメント → ⑪問い合わせに結果を返す
```

## 3. 後半（カスタムエージェント）

**起動：** 案件管理DB に案件が追加されたとき。条件は「仕入れ元区分＝問い合わせ」だけ。元問い合わせの有無は ① でエージェントが見る（無いと E08 の警告が出ないため）。
**モデル：** Sonnet 5.5。**作るのは大ちゃん。**
**読み書きするDB（E09）：** 案件管理DB・お問い合わせDB・企業マスター・売主交渉ログ・発電所情報入力DB・資料作成依頼DB・投資条件入力DB。
**手動の起動（E01）：** 人が押し直す方法が要る（12 の 2）。調べる必要あり：案件のボタンからエージェントを起動できるか。

### ① 起動の確認（E02・E03・R01・R02・E08）
- 起動した案件を対象に固定し、別の案件を推測して処理しない。案件を新規作成しない。
- 元問い合わせが無ければ、案件に警告を書いて終わる。引き継ぎ元を創作しない。複数あれば先頭だけ（E05）。
- ボタンを押した人（E03）：問い合わせに担当がいないとき（⑤）に使う。**エージェントが押した人を知る方法は調べる必要あり**（案件管理DB に「作成者」の列は無い）。

### ② 二重の確認（Q44・R03・R11）
- 元問い合わせに、この案件のほかの案件が紐づいていたら二重。**消さない。** 確認待ち内容と問い合わせの案件化メモに「同じ問い合わせの案件が既にあります：{案件}」（他の案件は最大5件。Q44）。
- 既定：二重のときは **補完しない**（子ページが増えるため）。記録は「警告して、起動された案件だけ補完」。12 の 3。

### ③ 前提の確認（足りなければここで止まる。④以降は動かない）
予定粗利は、問い合わせの案件化ボタンの説明どおり「どちらかが空だと案件化は止まり、理由は案件化メモに出る」。売主は大ちゃんの言葉（10/27）「売り手が設定されていなければエラー」。

| 前提 | 足りないとき |
|---|---|
| 売買区分が「売却相談」（Q22・G01） | 購入相談：案件化しない（購入のお客様はニーズの卵で対応。12 の 4）。不明・売買両方・その他相談：確認待ち。案件は消さない |
| 売主がいる（問い合わせ企業か問い合わせ個人） | ❌「売主が設定されていません」。直す場所を書く |
| 予定粗利額（正の数）と予定粗利の根拠が入っている（記録 §15-1 の3） | ❌「予定粗利が入っていません」。金額は推測で入れない |

止まったら、案件の確認待ち内容と問い合わせの案件化メモに理由を書き、問い合わせのフェーズ（推奨）を「要確認」にする。**ステータスは触らない。**

### ④ 売主（Q07・Q09・Q29・N05）
- 問い合わせ企業 → 案件の「問い合わせ企業」（Q07）と、売却案件なら **「売り手企業」**（Q09。空のときだけ）。
- 問い合わせ個人 → 案件の **「売り手個人」**。**記録に無い追加。** 問い合わせ個人は紹介者のこともある（列の説明「売主・紹介者の役割は案件側で区別する」）。既定：問い合わせ種別（法人／個人投資家／不明）が「個人投資家」のときだけ入れる。それ以外で企業が無ければ「売主が設定されていません」。12 の 5。
- **「関連企業」には入れない**（Q08 は記録にあるが、案件管理DB に列が無い）。名前の文字から企業や人を選ばない・作らない。

### ⑦ 名前（N01〜N15）
| 列 | 何 | 書き方 |
|---|---|---|
| **案件名** | **通称名**（営業が呼ぶ名前。例「松阪99キロ低圧」） | 空・受付番号・Aの仮名・**問い合わせの件名のまま**のときだけ付ける。人が決めた名前は変えない（N01・R06） |

- 材料が足りないときは **地名・規模・数量を作らない**。通称が付けられないときは、地域→規模→種別→紹介→第二プールの順に手掛かりと使用済みの名前を確かめて付ける。大型は番付＋通し番号（N11。語彙プールの中身は記録に無い。調べる必要あり）。

- **決めていただく**（記録 §11-7 の矛盾）：会社名を名前に使ってよいか（記録は「人と会社を材料にしない」と「会社名の芯を使ってよい」が同居）。文字数の上限（記録は「上限なし」と書き、採用の処理は24文字で切る）。

## 12. 決めていただくこと（上から順に大事）
1. **この設計図で進めてよいか。** 前半を標準の動き（Webhook なし）にすると、10/7 に Codex が実ボタンで確かめた次の動きが、前半では無くなる：既存の案件があれば更新して増やさない／購入相談・未確定で案件を作らない。後半のエージェントで「消さずに警告」までは再現するが、**案件が先に1件できる**ことは残る。
2. **前半が止められないための穴。** 購入相談・不足で押す → 空の案件が残る。直して再押下 → さらに1件増えて「二重」になる。消すのは人。これでよいか。直したあとにやり直す道（案件側に「案件化をやり直す」ボタンを置き、エージェントを起動する）を作るか。⏳ のまま残った案件の見つけ方（営業ボードで「⏳」を一覧する、など）も。
3. 二重のとき：**補完しない**（既定）か、記録どおり警告して補完するか。
4. 購入相談：このボタンの対象外として「⛔ 案件化しません」を出す（既定）。10/7 の Codex は、押されたら購入対応（企業連携・購入4条件・候補の提案・対応タスク）へ渡す形にしていた（記録 §17）。前半を標準にすると、その受け渡しはボタンからは動かない。購入のお客様は「ニーズの卵」の一覧から対応する形でよいか。
5. 個人の売主：問い合わせ種別が「個人投資家」のときだけ売り手個人に入れる（既定）でよいか。
6. 列「正式名称」にエージェントが入れるか（入れるなら形。例「三重松阪市太陽光発電所」）。名前に会社名を使ってよいか・文字数の上限。
7. 子ページ（発電所情報・資料作成依頼・投資条件）もエージェントが全部やるか。
8. 社外顧問・土地の部品を足す順番。

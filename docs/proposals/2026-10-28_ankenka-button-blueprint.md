## 0. 約束（大ちゃんが決めたこと）

- 案件化ボタンは **前半（ボタン）＋後半（オートメーション）**。**変えるのは後半だけ。** 後半を **カスタムエージェント** にする。全部は変えない。
- 売主は **売り手企業**（法人）か **売り手個人**（個人）に入れる。「関連企業」には入れない。
- 問い合わせの **担当営業ユーザー** は、案件化すると案件の **仕入れ担当** に移る。案件の **担当営業ユーザー**（販売側）は空で始まる。案件側で「商談をする」「担当になる」を押した人が、担当営業ユーザーになる。
- 名前は案件管理DB にもう決まっている：**案件名**＝営業が呼ぶ通称名、**正式名称（通称名）**＝対外用の名前。
- 購入希望のお客様は案件化しない。
- 本番を変える前に、大ちゃんに見せて OK をもらう。エージェントを作るのも、承認ボタンを押すのも大ちゃん。

## 1. 全体の流れ

```
お問い合わせ「案件化する」ボタン
│
├─ 前半（Notion 標準のボタン・AI なし・条件で止められない）
│    確認を表示 → 案件管理DB にページを追加 → 案件化メモに「受付」 → 追加した案件を開く
│
└─ 後半（カスタムエージェント・案件管理DB に案件が追加されたら起動）
     ① 起動の確認 → ② 二重の確認 → ③ 条件の確認 → ④ 売主 → ⑤ 担当
     → ⑥ 中身を移す → ⑦ 名前 → ⑧ 子ページの準備 → ⑨ 本文・コメント
     → ⑩ 問い合わせに結果を返す
```

## 2. 前半（ボタン）

10/6 までの形に戻す。AI を使わない Notion 標準の動き。**4つ。**

| 順 | 動き | 内容 |
|---|---|---|
| 1 | 確認を表示 | 「この問い合わせを案件にします。売主・予定粗利・🚦案件化可否を表示。購入希望のお客様に関しては案件化しない。」（文面は大ちゃんが決める） |
| 2 | 案件管理DB にページを追加 | 案件名＝問い合わせの件名／元問い合わせ＝このページ／仕入れ元区分＝問い合わせ／ステータス＝🔍 商談前 |
| 3 | このページを編集 | 案件化メモ＝「⏳ 案件化を受け付けました。中身はエージェントが埋めます」 |
| 4 | 追加したページを開く | 紐づいた案件を開く |

- 担当（仕入れ担当・担当営業ユーザー）は **ここでは入れない**。後半のエージェントが入れる（⑤）。
- 「仕入れ元区分＝問い合わせ」は、案件管理DB の自動化「案件化→内容引き継ぎ(B)自動発火」が、問い合わせの案件で二重に動かないようにするため。B の今の条件（仕入れ元区分が問い合わせ・土地情報ではない）はそのまま残す。
- 前半は **条件で止められない**（Notion のボタンの仕様）。購入相談・未確定でも、案件が先に1件できる。止める判断は後半（③）が行う。
- 調べる必要あり：ボタンの標準動作で、上の項目（元問い合わせ・仕入れ元区分・ステータス）を設定できるか。設定は API で読めず、画面でしか確かめられない。

## 3. 後半（カスタムエージェント）の部品

**起動：** 案件管理DB に案件が追加されたとき。仕入れ元区分＝問い合わせ、かつ元問い合わせが入っているときだけ。
**モデル：** Sonnet 5.5。**作るのは大ちゃん。**

### ① 起動の確認（E02・E03・R01）
- 起動した案件を対象に固定する。別の案件を推測して処理しない（R01）。案件を新規作成しない（R02）。
- 元問い合わせが無ければ、案件に警告を書いて終わる。引き継ぎ元を創作しない（E08）。
- 元問い合わせが複数あれば先頭だけを使う（E05）。
- ボタンを押した人（E03）を使う場面：問い合わせに担当がいないとき（⑤）。**エージェントが押した人を知る方法は調べる必要あり**（案件管理DB に「作成者」の列は無い）。

### ② 二重の確認（Q44・R03・R11）
- 元問い合わせに、この案件のほかの案件が紐づいていたら、二重。
- **消さない**（R03）。案件の確認待ち内容と問い合わせの案件化メモに「同じ問い合わせの案件が既にあります：{案件}」と書く。他の案件の表示は最大5件。
- 設計の選択（下の 12 の 2）：二重のときは **補完もしない**（子ページが増えるため）／記録どおり警告して補完する。

### ③ 条件の確認（G01〜G10、10/7 の C-1〜C-4）
**止めずに**、足りないものを案件の確認待ち内容に書く（不足チェックリスト。G08）。

| 条件 | 出どころ | 足りないときの動き |
|---|---|---|
| 売買区分が「売却相談」（案件の売買区分は「売却案件」になる） | G01・Q22 | 購入相談：案件化しない（Q43）。不明・売買両方・その他相談：確認待ち。どちらも案件は消さず、問い合わせのフェーズ（推奨）を「要確認」に |
| 売主がいる（問い合わせ企業か問い合わせ個人） | 大ちゃん 10/27（元の G02 では外れていた） | 「売主が設定されていません。先に『🔌企業連携を実行する』を押してください」 |
| 予定粗利額（正の数）と予定粗利の根拠 | 10/6 までの既存チェック（C-3） | 「予定粗利が入っていません」。金額は推測で入れない |
| 買い手の当て（案件の買い手企業） | G02 | 不足に載せるだけ。止めない |
| 対象物種別が確定している | G03 | 不足に載せるだけ |
| 決裁者の当て（決裁者名・接触確度・接点ログ） | G04 | 不足に載せるだけ |

- 販売価格が空でも止めない（G09）。条件を満たしても、ステータスを自動で進めない（G10）。
- 不足があっても案件のステータスは「🔍 商談前」に置く（G07）。**ただし、すでに進んだステータスは戻さない**（記録の §11-5 の欠陥を直す）。
- 確認待ち内容は、記録では置換（G08）。**人が書いた文は消さない**形にする（§11-4）。

### ④ 売主（Q07・Q09・Q29・N05）
- 問い合わせ企業 → 案件の「問い合わせ企業」（Q07）。売却案件なら案件の **「売り手企業」** にも同じ企業（Q09。空のときだけ）。
- 問い合わせ個人 → 案件の **「売り手個人」**（空のときだけ）。（Q 番号は無い。記録に無い追加）
- **「関連企業」には入れない**（Q08 は記録にあるが、案件管理DB に列が無く、効いていなかった）。紹介者を売主として入れない。
- 売主がつながっていないときは、名前の文字から企業や人を選ばず・作らない。会社名の文字は「売り手名メモ」（Q29）に残す。売主の実名は「相手先」（N05）。
- 売主をつなぐのは、問い合わせ側の「🔌企業連携を実行する」ボタンの役目（このエージェントはやらない）。

### ⑤ 担当（Q06・G05・G06・S13・S26・F28）
- 問い合わせの **担当営業ユーザー** → 案件の **仕入れ担当**（空のときだけ。最大5人）。問い合わせに担当がいなければ、ボタンを押した人。
- 案件の **担当営業ユーザー** は空のまま。仕入れ担当へ移した人は外す（G06。元の動きと同じ）。
- 元問い合わせの担当営業ユーザーは消さない。
- 案件側で「商談をする」「担当になる」を押した人が、案件の担当営業ユーザーになる。
- 子ページの担当営業ユーザー（S13・S26・F28）は、記録では「案件に担当がいれば引き継ぐ」。案件の担当営業ユーザーは空なので引き継ぐ人がいない。**子ページの担当をだれにするかは調べる必要あり／大ちゃんに確認**（12 の 6）。

### ⑦ 名前（N01〜N15）
| 列 | 何 | 書き方 |
|---|---|---|
| **案件名** | **通称名**。営業が呼ぶ名前（例「松阪99キロ低圧」） | 空・受付番号（「問-…」）・仮名のときだけ付ける。人が決めた名前は変えない（N01・R06） |
| **正式名称（通称名）** | **対外用の名前**（例「三重県松阪市 低圧セカンダリ案件（松阪99kW低圧）」） | 所在地・規模・対象物・案件種別・売買区分・通称から組み立てる。空のときだけ（N10） |
| 正式名称 | 例「三重松阪市太陽光発電所」（今 16件に入っている） | **記録に書き込む処理が無い。だれが入れているか調べる必要あり。** 決まるまでエージェントは触らない |

- 材料が足りないときは、**地名・規模・数量を作らない**。通称が付けられないときは、地域→規模→種別→紹介の手掛かりと使用済みの名前を確かめて付ける（N11。語彙プールの中身は記録に無い。調べる必要あり）。
- 採用しない名前：管理番号、日付だけの名前、「案件」「紹介案件」に逃げた名前。禁止：人物への評価、下品な語、事実に無い地名や数量（N12）。個人名を案件名に使わない（社外顧問の入口の決まり B02 に、ここもそろえる）。
- 付けた由来は、案件コメントに1行（N02）。
- 所在地・規模・相手先は、問い合わせの件名・本文から読めたものを案件に入れる（N03〜N05）。**記録では上書きだが、空のときだけにする**（§11-4）。
- 売買区分・案件種別・対象物種別が決まらないときは、AI で補う（N06・N08・N09）。選べる値は、案件種別：高圧・低圧・蓄電池・その他／対象物種別：太陽光発電所・系統用蓄電池・土地・その他。売買区分は「売却案件」以外を採用しない。根拠は案件コメントに（N07）。
- 子ページ（発電所情報・投資条件・資料依頼）のタイトルは、確定した案件名にそろえる。「｜」より後ろの用途名は残す。0件は失敗に数えない（N14・N15）。

### ⑧ 子ページの準備（S01〜S32・P01〜P39・F01〜F32・H01〜H33）
元の後半は、案件化のときに子ページも用意していた。**状態は「入力待ち」。完成資料は作らない**（S22）。

| 子ページ | 動き | 番号 |
|---|---|---|
| 発電所情報入力 | 関連が0件なら作る／1件なら使う／複数なら止めて整理を案内。タイトル「案件名｜発電所情報」。発電所名・所在地・住所を事前入力。案件に書き戻す（関連発電所情報・資料作成メモ・入力サポート） | S01〜S17 |
| 資料作成依頼 ×2 | 「案件名｜発電所資料出力」「案件名｜投資資料」。既存で対象案件・資料種別・価格版が一致するものは使う。価格は、商談の提示金額が先、無ければ設備入力の販売価格。古い価格版を現在版にしない | S18〜S32 |
| 事前入力（資料作成依頼） | 提案タイプ・価格・収入・設備詳細・金額内訳など（P01〜P39） | P01〜P39 |
| 投資条件入力 | 依頼の紐づき→同じ案件の検索で特定。複数なら止める。買い手企業は空のときだけ引き継ぐ（複数候補を1社に絞らない）。購入タイミング理由は「未判定」。顧客依頼文は作るだけで送らない | F01〜F32 |
| 不足項目の判定 | 33項目（H01〜H33）。「28項目」ではない | H01〜H33 |

- **土地由来の問い合わせは、発電所情報入力だけ用意し、投資条件・提案資料は省く**（S00）。「土地由来」の判定条件は記録に無い。調べる必要あり。
- 複数あれば止めて整理を案内する。先頭の1件を正解にしない・消さない（姫路の例）。
- **今の案件管理DB に無い列**があり、そこは読めない・書けない（6 を参照）。

### ⑨ 本文・コメント（C01〜C16）
- 案件の本文に営業案内（営業サマリーと次の一手・元問い合わせ・確認待ち・設備入力→資料/投資条件→資料/商談の案内）。問い合わせ本文は、意味のある部分だけ、最大80行・1行1,800文字で追加（C01・C02）。「営業サマリーと次の一手」が既にあれば、どちらも追加しない（C03）。
- コメント：引き継ぎ元なし・購入相談で停止・二重・命名の由来と売買判定の根拠・子ページ名のそろえ結果（C04〜C08）。不足は確認待ち内容へ、子ページ準備の結果は入力サポートへ（C09〜C12）。
- コメントは最大1,800文字（C16）。

### ⑩ 問い合わせに結果を返す（Q31〜Q41）
問い合わせの **今ある列だけ** に書く：ステータス＝「案件化」、問い合わせフェーズ（推奨）、紐づき案件（既存と統合）、案件化メモ。
問い合わせに無い列（進捗フェーズ・案件化日・最終アクション日・関連案件・営業サマリー・次の一手・案件化実行者）は書かない（6 を参照）。

## 4. 結果の出し方（案件化メモ。問い合わせ側）

| 結果 | 案件化メモ | 問い合わせのフェーズ（推奨） |
|---|---|---|
| 成功 | ✅ 案件にしました：{案件名}。売主：{売り手企業か売り手個人}。担当：{仕入れ担当}。予定粗利：{額}（{根拠}） | 案件化候補 |
| 案件はできたが不足あり | ⚠ 案件はできました。要確認：{足りないもの}。{直す場所} | 要確認 |
| 購入相談・未確定 | ⛔ 案件化しません：{理由}。（案件管理DB に空の案件が残る。消すのは人） | 要確認 |
| 二重 | ⚠ 同じ問い合わせの案件が既にあります：{案件} | 要確認 |
| 途中で失敗 | ❌ 途中で止まりました：{理由} | 要確認 |

- **止まったのに「完了」と書かない**（R13。10/6 の欠陥）。押す前や処理の途中に完了と見せない。

## 5. 落としてはいけない決まり（R01〜R15 のまとめ）
- 押された案件を対象にする／案件を新規作成しない／重複を勝手に消さない（R01〜R03）。
- 人が入れた値を守る：金額・仕入れ元区分・確定した名前は空のときだけ（R04〜R06）。
- 原データと AI の補完を分け、AI の判断には根拠を残す（R07）。
- 既存企業の状態を後退させない（R08）。
- 選択肢・列・型は実在を確かめる。**列・DB・選択肢を作らない**（R09）。
- 子ページ・資料の版を取り違えない。先頭の1件で隠さない（R10）。
- 繰り返し押されても二重に追加しない（R11）。検索は全件を最後まで読む（R12。元は20件の1ページだけだった）。
- 途中の失敗を成功に見せない（R13）。担当の移動は省かない（R14）。
- 実ボタンで確かめる。AI が結果を直接書いて証拠にしない（R15）。
- メール送信・外部送信・削除はしない。顧客向け資料の完成出力はしない（§10）。

## 6. 今の案件管理DB・問い合わせDB に無い列（書けない・書かない）

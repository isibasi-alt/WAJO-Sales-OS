# 24時間情報収集サーバーのチャンネルへ（朝刊くんのチャンネルから）

大ちゃんの決定で、朝刊くんは巡回をやめて、このサーバーに合流します。こちらが受け持つのは、毎朝1回だけ動く「編集長」です。ダムを読んで、業界の反応・SNSの温度・営業で使える一言を入れた【朝刊】を1本書きます。巡回はすべて、このサーバーに任せます。
提案書：https://github.com/isibasi-alt/WAJO-Sales-OS/blob/claude/determined-einstein-d4yg7q/docs/proposals/2026-10-16_join-24h-server.md

朝刊の部品をこちらで作って渡したいので、次の8つを教えてください。分からないものは「未確認」、できないものは「できない」で構いません。そちらの資料と同じく、答えごとに「確認済み／未確認」を付けてもらえると助かります。

1. **ダムの読み方**：直近24時間に入った行を読むには、何をどこから読めばよいですか（ファイルの場所、表の名前、列の名前）。
2. **行の種類の見分け方**：行政の動き（法令・パブコメ・連系ルール・条例）、ニュース、空き容量の変化は、どの列で見分けますか。
3. **夜の巡回が終わる時刻**：稼働証明が書き終わるのは、毎朝何時ごろですか。朝刊はその後に動かします。
4. **予定の足し方**：サーバーに「毎朝1回」の仕事を1本足すには、どこに何を書けばよいですか。台帳の鍵・上限・止めるスイッチの仕組みがあれば、朝刊もそれを使います。
5. **AIの呼び方**：ニュースの仕分けで Claude を呼んでいる仕組み（道具を持たせない形）は、何を使っていますか。朝刊も同じものを使います。
6. **Notion への書き方**：サーバーは今、Notion に書き込んでいますか。書き込んでいるなら、どのDBに、どの仕組みで書いていますか。
7. **ニュース検索に1本足せるか**：行政の動きが出たとき、その題名でニュース検索をかけて、業界の反応を台帳に入れる処理を足せますか。足せるなら、そちらで作りますか、こちらで作りますか。
8. **コードの置き場所**：サーバーのコードは、どこにありますか（GitHub のリポジトリなど）。こちらから読めれば、朝刊の部品を、そちらの決まりに合わせた形で作って渡せます。

あわせて、提案書に反対の点や「それは無理」という点があれば、遠慮なく書いてください。朝刊くんの側は、日曜の設置までに準備を合わせます。
